AKK OPERASIONAL - LAPORAN AUDIT FINAL V2 (HOSTINGER + MYSQL)
Tanggal audit: 27 Oktober 2026
Domain produksi: https://akkoperasional.com

RINGKASAN TEMUAN & PERBAIKAN V2
1. Bootstrap Super Admin (server.ts):
   - Sebelumnya: jika email sudah pernah ada di tabel users, ON DUPLICATE KEY UPDATE hanya mengubah role & status tanpa memperbarui password_hash.
   - Sekarang: password_hash = VALUES(password_hash) ikut diperbarui dengan hash bcrypt dari BOOTSTRAP_ADMIN_PASSWORD.
2. Konteks AI & OCR Dinamis (server.ts):
   - Sebelumnya: daftar nama driver dan plat nomor armada tertulis statis di prompt AI/OCR.
   - Sekarang: buildLiveOperationalContext() mengambil daftar armada dan kru langsung dari MySQL Hostinger.
3. Penghapusan Fallback Data Kru Palsu (src/services/store.ts):
   - Sebelumnya: frontend dapat mengarang nomor HP, nomor SIM, 18/150 trip, rating 4.9, sertifikasi, dan memilih armada pertama secara otomatis.
   - Sekarang: seluruh nilai mengarang dihapus; field yang belum diisi tetap kosong/'-' dan dinilai dari data aktual.
4. Penghapusan Data Mock Produksi (src/data/mockData.ts, store.ts, driverChecklistService.ts, driverReportService.ts, attendanceService.ts):
   - Sebelumnya: profil user, armada, kru, toko, jadwal, GPS, checklist, dan report contoh masih bisa muncul sebagai fallback.
   - Sekarang: seluruh INITIAL_* di-gate pada mode development saja (!IS_PROD_BUILD) dan service tidak lagi melakukan auto-seed data sampel.
5. Pembersihan PIN 1234 & Masking PIN (src/services/driverShiftService.ts, src/components/DriverCheckinModal.tsx, src/services/e2eTestRunner.ts):
   - Sebelumnya: PIN default '1234' aktif bila driver belum membuat PIN, dan nilai PIN tampil terang di catatan laporan.
   - Sekarang: driver wajib membuat PIN terlebih dahulu, dan nilai PIN disamarkan menjadi '****' di seluruh log/notifikasi.
6. Driver Waybill Jujur terhadap Data Kosong (src/services/driverWaybillService.ts):
   - Sebelumnya: mengarang 'Ach Taufiq', '0812-3456-7890', 'P 8848 U', 'Engkel Long Box', gate-out '07:30 WIB', ETA '14:00 WIB', dan 'Bpk. Herman'.
   - Sekarang: menggunakan '-' atau '' jika data jadwal/armada/kru belum diisi.
7. Pelabelan Demo OCR (src/components/DocumentScannerModal.tsx):
   - Sebelumnya: tombol sampel mengisi nomor surat jalan terlihat operasional dengan status 'verified'.
   - Sekarang: berawalan DEMO-, diberi catatan [CONTOH DEMO — BUKAN DOKUMEN OPERASIONAL], dan berstatus 'pending_review'.
8. Validasi Koordinat Toko (server.ts, src/components/CustomerMapping.tsx):
   - Sebelumnya: koordinat kosong/invalid diganti koordinat default (-8.219, 114.369) atau offset acak.
   - Sekarang: API backend menolak koordinat invalid (HTTP 400) dan import Excel melewati/menolak baris tanpa koordinat valid.
9. Penguatan RBAC Backend (server.ts):
   - Endpoint Armada (requireFleetWrite), Crew (requireCrewWrite), Toko (requireStoreWrite), Jadwal (requireScheduleWrite), Attendance (requireAttendanceWrite), dan validasi spreadsheet (/api/validate-schedule-spreadsheet) dilindungi RBAC server-side.
10. Production Fail-Fast (server.ts):
    - Jika NODE_ENV=production dan konfigurasi MySQL Hostinger, SESSION_SECRET, atau hasil build dist/index.html belum tersedia, server langsung keluar dengan kode error (exit 1) dan tidak diam-diam masuk ke mode development.
